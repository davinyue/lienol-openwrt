# x86_64 Linux 6.18.63 构建错误修复

## 背景

x86_64 已切换到 Linux 6.18.63，执行完整构建时发现 6.18 通用补丁队列含有已进入上游的重复补丁，随后在 NFS RPCSEC 内核包阶段因缺少 `krb5.ko` 的包依赖而失败。

## 目标

修复 x86_64 Linux 6.18.63 的补丁应用和模块打包错误，并完成当前 `.config` 选定目标的构建。

## 范围

- 清理与 Linux 6.18.63 上游源码重复的 6.18 backport/pending 补丁。
- 将仍然需要的补丁上下文更新到 6.18.63，并保留已有错误处理。
- 为 `rpcsec_gss_krb5.ko` 补齐 `krb5.ko` 的内核包依赖。
- 重跑 x86_64 完整构建并记录结果。

## 非目标

- 不修改其他目标平台的默认内核版本或无关包配置。
- 不改变 NFS RPCSEC 功能选择。

## 关键设计

先将失败 hunk 与干净的 Linux 6.18.63 源码比较：若修复已在上游则从 6.18 队列移除重复补丁；若仍需修复则更新上下文并保留原有错误路径。将 `crypto/krb5/krb5.ko` 映射到独立内核包，并让 NFS RPCSEC 包依赖该包。

## 验收标准

- Linux 6.18.63 源码准备和补丁应用通过。
- `kmod-fs-nfs-common-rpcsec` 及其 `krb5.ko` 依赖可正常打包。
- x86_64 完整构建成功，或准确记录仍阻塞构建的错误。
- `git diff --check` 通过。
